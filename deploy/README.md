# «Вахта» на своём сервере

Серверный режим запускает ту же службу и тот же веб-интерфейс, что и
приложение для Windows, но без окна, трея и инсталлера. Интерфейс
открывается в браузере, вход по паролю. Подходит для домашнего сервера,
NAS или VPS: компьютер можно выключать, а фарм продолжается.

**Один экземпляр — один аккаунт Twitch.** Нужно два аккаунта — запустите два
контейнера с разными томами данных.

## Быстрый старт (Docker Compose)

1. Соберите образ из корня репозитория:

   ```bash
   docker build -f deploy/Dockerfile -t vahta .
   ```

2. Создайте пароль панели: случайная строка не короче 20 символов.
   Не передавайте его аргументом командной строки и не коммитьте.

   ```bash
   mkdir -p secrets data
   python3 -c "import secrets; print(secrets.token_urlsafe(24))" > secrets/web_password
   sudo chown -R 10001:10001 secrets data
   chmod 0400 secrets/web_password && chmod 0700 data
   ```

3. Скопируйте [docker-compose.example.yml](docker-compose.example.yml)
   в `docker-compose.yml`, впишите свой адрес и адрес прокси, затем:

   ```bash
   docker compose up -d
   ```

4. Откройте свой адрес, войдите с паролем из `secrets/web_password`
   и в «Настройках» войдите в Twitch: Twitch покажет код, его нужно
   ввести на twitch.tv/activate.

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `VAHTA_PUBLIC_URL` | да | Адрес, по которому вы открываете панель, например `https://vahta.example.com`. По нему проверяются `Origin` и `Host`. |
| `VAHTA_PASSWORD_FILE` | да | Путь к файлу с паролем панели внутри контейнера. |
| `VAHTA_TRUSTED_PROXY` | да | IP обратного прокси, которому можно верить в `X-Forwarded-*`. Только конкретный адрес, не `*`. |
| `VAHTA_DATA_DIR` | нет | Папка данных, в образе — `/data`. Её нужно смонтировать постоянным томом. |
| `TZ` | нет | Часовой пояс для журналов и расписания, например `Europe/Moscow`. |

`VAHTA_SERVER=1` выставляет сам образ. Процесс должен быть один: несколько
воркеров Uvicorn запустили бы несколько фармов на одном аккаунте.

## Обратный прокси

Панель слушает порт 8420 внутри контейнера и рассчитана на работу за
обратным прокси с HTTPS (Caddy, nginx, Traefik). Прокси обязан передавать
исходный `Host` и `X-Forwarded-Proto`. Публиковать порт 8420 напрямую
в интернет не нужно.

Пример для Caddy:

```
vahta.example.com {
    reverse_proxy vahta:8420
}
```

## Безопасность

- Cookie сессии — `Secure`, `HttpOnly`, `SameSite=Strict`, живёт 30 дней.
  Замена файла пароля и перезапуск сбрасывают все прежние сессии.
- Изменяющие запросы требуют точного `Origin`, совпадающего с `VAHTA_PUBLIC_URL`.
- `/healthz` отвечает без входа только с loopback самого контейнера
  и проверяет, что цикл службы не завис.
- Приложение работает от UID/GID 10001. Владелец `/data` и файла
  пароля — этот пользователь. Права: `/data` — 0700, файлы данных — 0600,
  пароль — 0400.
- `data/auth.json` — это полный доступ к аккаунту Twitch. Резервируйте
  `/data` так же бережно, как пароли.

## Данные и журналы

Всё состояние лежит в `/data`: `vahta.db` (SQLite), `auth.json`,
`settings.json`, `telegram.json`, при наличии — `games.json.gz`.
Журнал пишется в `/data/logs/vahta.log` (4 файла по 2 МБ) и в stdout контейнера.

Обновление — пересборка образа из свежего кода и `docker compose up -d`.
Данные в томе при этом не трогаются. Windows-инсталлеры в серверном режиме
не скачиваются и не запускаются, а база игр для подсказок по-прежнему
обновляется из релизов GitHub.

## Перенос с ПК на сервер

1. Закройте «Вахту» на ПК через меню трея и выключите её автозапуск.
   Дождитесь, пока процесс действительно завершится.
2. Сделайте согласованную копию базы, а не копию файла на ходу:

   ```bash
   python -c "import sqlite3; s=sqlite3.connect('vahta.db'); d=sqlite3.connect('vahta-copy.db'); s.backup(d); print(d.execute('PRAGMA integrity_check').fetchone())"
   ```

3. Перенесите в `/data` копию базы под именем `vahta.db`, а также `auth.json`,
   `settings.json`, `telegram.json` и, если есть, `games.json.gz`.
   Не переносите exe, кеш WebView, логи и файлы `-wal`/`-shm`.
4. Не запускайте старый и новый экземпляры одновременно: два фарма на одном
   аккаунте рассинхронизируют прогресс дропов.
5. Сравните в панели список игр, награды и историю, затем убедитесь, что
   минуты на Twitch снова растут.

## Тесты

Тесты запускаются отдельными процессами: часть файлов завершает работу
через `sys.exit`, поэтому `unittest discover` для всей папки не подходит.

```bash
for t in tests/test_*.py; do python "$t" || echo "FAIL $t"; done
```

`tests/test_server_mode.py` проверяет авторизацию и защиту серверного режима.
Автоматические проверки не заменяют живой прирост минут на Twitch.
