# Вахта

Бесплатный инструмент с открытым исходным кодом, который сам собирает
Twitch-дропсы и планирует просмотр по нескольким играм с учётом дедлайнов
и того, когда по игре вообще идут эфиры. Каталог кампаний, вотчлист,
расписание, инвентарь, уведомления Windows и Telegram.

Работает двумя способами — код и интерфейс у них общие:

| | Где живёт | Как открывается |
|---|---|---|
| **Приложение для Windows** | на вашем компьютере, в трее | своё окно; инсталлер и автообновление из релизов GitHub |
| **Свой сервер** | Docker на домашнем сервере, NAS или VPS | браузер, вход по паролю — [как запустить](deploy/README.md) |

Никаких промокодов, платных функций, аккаунтов и телеметрии: «Вахта» ходит
только в Twitch, в Telegram (если вы подключили бота) и на GitHub — проверить
новую версию. Лицензия — [MIT](LICENSE).

> **Риск.** Автоматизация просмотра формально противоречит условиям Twitch.
> Держите ферму на отдельном аккаунте. «Вахта» использует приватный API Twitch,
> и когда Twitch его меняет, программа временно ломается до обновления.

## Как работает

Видео не скачивается. «Вахта» получает HLS-плейлист и примерно каждые 20 секунд
проверяет его сегменты запросами HEAD, без загрузки тел видео и аудио.
Засчитанные минуты и награды читает из Twitch. Старые `minute-watched`-пинги
заменены 10 октября 2026 после остановки прогресса EXFIL Brothers.

**Успешный сетевой запрос не доказывает рост прогресса.** `dropCurrentSession`
может отдавать прежнее число или сессию другого канала. Узнать, жив ли эфир,
можно только спросив. [vahta/watcher.py](vahta/watcher.py) поэтому переспрашивает
состояние стрима **каждый круг** — ушедший стример и сменённая игра уводят
с канала за минуту, а перезапуск эфира не уводит вовсе, только обновляет номер
трансляции. Плюс сторож на единственный оставшийся случай: если эфир идёт,
а засчитанные минуты не растут пять тиков подряд — меняем канал.

Кампании и прогресс читаются через приватный GraphQL API Twitch
(`gql.twitch.tv`); события просмотра отправляются отдельно на телеметрию Twitch.
Документации по нему нет, хэши запросов лежат в [vahta/constants.py](vahta/constants.py).
Когда Twitch меняет схему, чинить нужно в первую очередь там: признак —
ошибка `PersistedQueryNotFound`. Зависимость от приватного API Twitch —
известный риск: внешние изменения могут потребовать обновления приложения.

## Служба и интерфейс

Фарм, планирование и данные живут в [vahta/service.py](vahta/service.py) —
**в своём потоке со своим циклом событий**. Веб-интерфейс
([vahta/web.py](vahta/web.py)) ничем не владеет: он только превращает
состояние службы в JSON. Поэтому интерфейс можно уронить, перезапустить или
не поднимать вовсе — вахта продолжается.

Отсюда правило, которое легко нарушить и трудно заметить: **`store` и `tw`
трогаются только из потока службы.** Соединение sqlite3 привязано к своему
потоку, а `Twitch` — к своему циклу. Всё, что их касается, оформляется
функцией от службы и уходит в `service.call(...)`:

```python
rows = await svc().call(lambda s: s.store.watchlist())
```

Проверяет это [tests/test_service.py](tests/test_service.py): там веб-слой
перезапускается на живой службе, а обращение к базе мимо `call` падает
с `ProgrammingError` — как и должно.

Потоков в приложении четыре, и порядок запуска в [vahta/app.py](vahta/app.py)
не случайный: главный поток обязан достаться окну (`webview.start()` иначе
не работает), поэтому трей уходит в `run_detached()`, а сервер и служба —
в свои потоки. Окно создаётся последним.

## Установка

Готовая «Вахта» ставится инсталлером `Vahta-Setup-<версия>.exe`: на
пользователя, в `%LOCALAPPDATA%\Programs\Vahta`, без прав администратора.
Он же предлагает ярлык и автозапуск, а при удалении спрашивает, удалять ли
данные — вход в Twitch и историю. Установка поверх старой версии
данные не трогает.

Инсталлер лежит в [релизах на GitHub](https://github.com/ksenobeat/twitch_drops_farmer_vahta/releases).
SmartScreen предупредит при скачивании: exe не подписан. Не доверяете
готовой сборке — соберите сами из исходников, это пара команд.

Из исходников:

```bash
py -3.12 -m venv env
env\Scripts\python.exe -m pip install -r requirements.txt
```

Сборка своей версии — [installer/README.md](installer/README.md):

```bash
env\Scripts\python.exe build.py
"%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" installer\vahta.iss
```

## Использование

Запусти **Вахта.exe**. Появится иконка в трее и своё окно — WebView2, без
адресной строки и вкладок. Крестик закрывает окно, но не программу: фарм
продолжается, выход через меню иконки. Это переключается в настройках.

В первый раз окно встречает мастером из четырёх шагов: вход в Twitch, игры под
фарм, привязка игровых аккаунтов и поведение — крестик, автозапуск,
уведомления. Пропустить можно на любом шаге, всё это лежит и в «Настройках».

Иконка в трее живая: средняя полоса знака растёт по прогрессу текущей смены
и краснеет, когда план перестал сходиться.

Титульная строка своя, а не системная: знак, «ВАХТА» и три кнопки справа.
За строку окно таскают, двойной клик по ней разворачивает. Тянуть за края,
разворачивать через `Win+↑` и прилипать к краям экрана окно не разучилось —
рамка ему возвращена, просто её не видно.

Слева — переходы по экранам со счётчиками: сколько конфликтов, игр, кампаний
в каталоге. Под ними — сколько идёт нынешняя смена: отсчёт начинается с первой
засчитанной Twitch минуты и обнуляется, если эфир оборвался. Снизу узкая
строка: идёт ли фарм, сколько уходит трафика, когда ближайший дедлайн, на
связи ли Telegram и какая стоит версия.

Тема — «как в системе», тёмная или светлая, переключается в настройках.
Системная подхватывается на лету, перезапуск не нужен.

**Окно живёт только пока открыто.** Крестик его не прячет, а уничтожает —
и возвращает системе около 460 МБ, которые занимает WebView2. Открывается оно
заново мгновенно, а «Вахта» в трее всё это время стоит столько же, сколько
любая фоновая мелочь. При запуске вместе с Windows окно не открывается вообще,
пока его не попросят.

Размер и положение окна запоминаются, как и то, что оно было развёрнуто. Если
монитор, на котором оно стояло, отключили — откроется по центру, а не за краем
экрана.

**Экземпляр всегда один.** Второй запуск по ярлыку не поднимает вторую
«Вахту», а открывает окно уже работающей. Иначе два фарма смотрели бы Twitch
одним аккаунтом — и прогресс дропов рассинхронился бы.

Движка ставить не нужно: WebView2 предустановлен на всех Windows 11 и на
Windows 10 начиная с обновления 2018 года. На редких машинах без него «Вахта»
не падает, а показывает интерфейс в браузере и живёт одним треем.

В меню трея: открыть окно, папка с данными, запуск при входе в систему, выход.

## Уведомления

Windows покажет всплывающее окно, когда забран дроп, открылась кампания из
вотчлиста, план перестал сходиться или протух токен Twitch. Окно «Вахты» для
этого держать не нужно — сообщения падают в центр уведомлений, как у любой
другой программы.

Шлёт их иконка в трее: Windows сама превращает её подсказку в тост. Поэтому
отдельной библиотеки и ярлыка в меню «Пуск» не требуется — и поэтому же при
запуске `serve` без трея показывать нечем, о чём в настройках честно написано.
(`AppUserModelID` «Вахта» всё-таки регистрирует, но не ради уведомлений:
без него панель задач считает её окно окном python.exe.)

Пока окно открыто, о том же самом говорит свой тост в правом нижнем углу —
он живёт четыре секунды и не ждёт, пока его заметят. Системное уведомление
нужно для обратного случая: окна нет, а сказать надо.

Переключатель и кнопка **«Проверить»** — на вкладке «Настройки». Кнопка нужна
не для красоты: тост глушат «Фокусировка внимания», полноэкранный режим и
системные параметры уведомлений, и без неё непонятно, где искать причину.
Выбор лежит в `data/settings.json`.

Данные (`auth.json`, база, настройки) лежат в папке `data` рядом с exe. Если
положить exe в `Program Files`, где писать нельзя, — уедут в `%LOCALAPPDATA%\Vahta`.

## Сеть и приватность

«Вахта» разговаривает только с тремя сторонами:

- **Twitch** — кампании, прогресс, просмотр и получение дропов;
- **Telegram** — только если вы сами вставили токен своего бота;
- **GitHub** — раз в шесть часов обычный анонимный запрос к API релизов:
  есть ли новая версия и свежая база игр. Выключается переключателем
  «Обновлять автоматически»; тогда проверка — только по кнопке.

Своего сервера у проекта нет: ни телеметрии, ни идентификатора установки,
ни отпечатка компьютера.

Из исходников то же самое:

```bash
env\Scripts\python.exe main.py                     # окно и трей
env\Scripts\python.exe -m vahta.cli serve --open   # без окна: служба, сервер и браузер
```

`serve` пригождается для отладки: есть консоль, интерфейс открывается в
браузере, а трея нет — значит нет и уведомлений.

Посмотреть на интерфейс, не поднимая фарм:

```bash
env\Scripts\python.exe tools\preview.py
```

Настоящее окно и настоящая вёрстка, но вместо Twitch — выдуманный JSON в словаре
`FAKE`. Аккаунт не трогается, в базу ничего не пишется. Нужно потому, что до
половины состояний на живых данных не дотянуться по заказу: конфликт дедлайнов,
кампания без привязанного аккаунта, игра без замеров, пауза.

## Сборка

```bash
env\Scripts\python.exe -m pip install pyinstaller
env\Scripts\python.exe build.py
```

Получается папка `dist\Вахта\` с exe и зависимостями (`onedir`), без консоли.
Для раздачи затем собирается `Vahta-Setup-<версия>.exe` через Inno Setup —
см. [installer/README.md](installer/README.md).

Экраны в окне:

| | |
|---|---|
| Сейчас | что фармится, очередь, конфликты с кнопками разбора |
| Расписание | диаграмма Ганта на две недели, под ней таблица с запасом |
| Мои игры | вотчлист и приоритеты: номер можно вписать, а можно перетащить |
| Каталог | все активные кампании Twitch — что подключить и что привязать |
| Инвентарь | награды с Twitch за всё время плюс наши часы по играм |
| Настройки | аккаунт Twitch, токен Telegram, тема, уведомления, обновления |

Слушает только localhost, авторизации нет и не нужно.

### Расписание

Полоса Ганта отвечает на «когда и сколько», таблица под ней — на «сколько
запаса и почему». **Толщина полосы — доля эфира:** кампании идут вперемешку
и полосы пересекаются, потому что эфир делится, а не резервируется; одинаковая
толщина у двух пересекающихся полос читалась бы как «обе фармятся целиком»,
а так не бывает. Пунктирный штрих поперёк строки — дедлайн.

Шкала кончается на самом дальнем из концов работы и дедлайнов, а не через
14 дней: горизонт плана — это потолок, иначе одна кампания с дальним дедлайном
сплющила бы остальные в первый пиксель.

### Инвентарь

Twitch не говорит, к какой игре относится награда — `game` пустой у всех до
единой. «Вахта» подставляет игру там, где id награды сошёлся с benefit'ом
знакомой кампании: после одного обхода это два десятка наград из полутора
сотен. Остальное **можно вписать руками** — прямо в строке. Вписанное сильнее
подстановки и переживает обходы; стёртое поле возвращает автоматику.

### Каталог

Показывает все активные кампании (обычно около сотни). Четыре фильтра:

| фильтр | что показывает |
|---|---|
| Доступны мне | кампании, где игровой аккаунт уже привязан — по умолчанию фармятся они |
| Без привязки | **игры**, по которым кампании есть, но не привязано ничего |
| Все | весь каталог |
| В вотчлисте | кампании по играм, за которыми уже следим |

У каждой непривязанной кампании стоит ссылка **«привязать»** на сайт издателя —
Twitch сам отдаёт её в `accountLinkURL`. Кнопка **«Следить»** добавляет игру
в вотчлист. Есть поиск по игре, кампании и издателю.

«Без привязки» группирует по играм, а не по кампаниям: привязка одна на игру,
и пять строк Rust вместо одной были бы шумом. В этом фильтре показывается
предупреждение — следить можно уже сейчас, но при настройках по умолчанию
фарм не начнётся, пока игровой аккаунт не привязан.

Поле «добавить игру» подсказывает названия из локальной базы игр Twitch,
которая поставляется с приложением. Игру можно добавить заранее, даже если
сейчас по ней нет дропсов: обход заметит появление кампании.

### Вход в Twitch

На вкладке «Настройки». Twitch выдаёт короткий код, его нужно ввести на его же
сайте — пароль в «Вахту» не вводится и нигде не хранится. Интерфейс поднимается
и без входа, так что если токен протух, войти можно прямо оттуда.

Сам батник написан **только латиницей**: cmd читает `.bat` побайтово, и
кириллица внутри сбивает разбор строк — особенно после `chcp`. Все сообщения
для человека печатает Python, там с UTF-8 всё в порядке.

## CLI

```bash
env\Scripts\python.exe -m vahta.cli login
```

Покажет код и ссылку — вводишь код на twitch.tv, токен сохранится в `data/auth.json`.

```bash
env\Scripts\python.exe -m vahta.cli campaigns          # все активные кампании
env\Scripts\python.exe -m vahta.cli channels "Rust"    # кто в эфире и какую кампанию крутит
env\Scripts\python.exe -m vahta.cli watch "Rust"       # фармить
env\Scripts\python.exe -m vahta.cli watch "Rust" --unlinked  # и без привязки игрового аккаунта
env\Scripts\python.exe -m vahta.cli inventory          # прогресс по кампаниям в процессе
env\Scripts\python.exe -m vahta.cli inventory --rewards  # и все полученные награды списком
env\Scripts\python.exe -m vahta.cli claim              # забрать готовое
env\Scripts\python.exe -m vahta.cli history            # что отфармлено, по играм
env\Scripts\python.exe -m vahta.cli history Overwatch  # дропы одной игры
env\Scripts\python.exe -m vahta.cli uptime             # как часто по игре есть эфир с дропсами
```

### Вотчлист

Игру можно добавить до того, как по ней появится кампания — сканер сам заметит,
когда она откроется.

```bash
env\Scripts\python.exe -m vahta.cli watchlist-add "Rust"
env\Scripts\python.exe -m vahta.cli watchlist-move "Rust" 1   # порядок = приоритет
env\Scripts\python.exe -m vahta.cli watchlist-rm "Rust"
env\Scripts\python.exe -m vahta.cli watchlist
env\Scripts\python.exe -m vahta.cli scan                      # разовый обход
env\Scripts\python.exe -m vahta.cli scan --loop               # в фоне, раз в 30 мин
```

Игры хранятся по id, а не по названию: в каталоге игра может называться
«Overwatch 2», а в кампании — «Overwatch». При добавлении название сверяется
с Twitch, опечатки отсекаются сразу.

`watch` держит один канал, опрашивает HLS и раз в минуту проверяет прогресс. Когда дроп
готов — забирает его и переходит к следующему. Если стример ушёл в офлайн или
выключил дропсы, ищет другой канал по той же игре.

## Важное

- **Фарм без привязки игрового аккаунта по умолчанию выключен.** Это решение
  подтверждено 8 сентября 2026: `farm_unlinked=False` сохраняется. Рост минут
  без привязки подтверждён автором 3 августа; получение предмета в самой игре
  требует привязки. Ручная настройка «кампании без привязки» и CLI-флаг
  `--unlinked` остаются доступны, автоматически включать их не нужно.
- **Отдельный аккаунт под ферму.** Дроп падает в игровой аккаунт, привязанный к
  тому Twitch-аккаунту, который смотрел. После перепривязки основной Twitch по
  этим играм дропсы получать перестанет.
- **Одна игра — это не одна кампания.** По Rust, например, одновременно идут
  четыре, и какая из них тебе доступна, зависит от того, кто сейчас в эфире:
  живые каналы могут крутить совсем не ту, что кончается раньше всех. Смотри
  `channels <игра>` — там видно, кто какую кампанию отдаёт.
- Не смотреть Twitch тем же аккаунтом параллельно — прогресс рассинхронится.
  Признак в логе: «Twitch не видит активной дроп-сессии».
- `data/auth.json` — это полный доступ к аккаунту. Лежит вне git.
- Автоматизация просмотра формально против Twitch ToS.

## Telegram

Работает через long polling — вебхук, белый IP и открытые порты не нужны.

Токен от [@BotFather](https://t.me/BotFather) вставляется на вкладке
**Настройки** — он проверяется через `getMe` и сохраняется только если Telegram
его принял, а бот поднимается сразу, без перезапуска сервера. Наружу токен
не отдаётся, в интерфейсе видно только хвост.

Через CLI то же самое:

```bash
env\Scripts\python.exe -m vahta.cli telegram <токен от @BotFather>
```

Дальше напиши боту `/start`. **Первый написавший становится владельцем**,
все остальные чаты потом игнорируются — иначе любой, кто найдёт бота,
управлял бы твоей фермой.

Команды: `/status`, `/plan`, `/watchlist`, `/add <игра>`, `/history [игра]`,
`/pause 2ч`, `/pause off`.

Сам присылает: открылась кампания по игре из вотчлиста, забран дроп,
и конфликт дедлайнов — с кнопками выбора.

### Как разбираются конфликты

Любой выбор сводится к одному действию — отключить какую-то кампанию, чтобы
освободить эфир остальным. «Дожать A» означает отказаться от соперника B,
«отказаться от A» — от самой A. Поэтому кнопка всегда делает ровно одно
понятное действие, а не запускает скрытую перестановку приоритетов.
Отключённые кампании лежат в таблице `skipped` и исключаются из плана.

## Обновления

О свежей версии «Вахта» узнаёт из последнего релиза на GitHub
([vahta/releases.py](vahta/releases.py)). Инсталлер `Vahta-Setup-<версия>.exe`
качается заранее, сверяется с SHA-256, который GitHub сам считает для каждого
файла релиза, и ставится **между ломтями фарма** — посреди просмотра обновление
стоило бы минут, которые Twitch не вернёт. Тихо, без вопросов и без
перезагрузки; данные и вход в Twitch не трогаются. Не встало — «Вахта»
продолжает работать в прежней версии.

Форк, который раздаёт свои сборки, указывает свой репозиторий переменной
`VAHTA_UPDATE_REPO=владелец/имя`.

### Как выпустить версию

1. Поднять `__version__` в [vahta/__init__.py](vahta/__init__.py).
2. Собрать инсталлер — см. [installer/README.md](installer/README.md).
3. Создать релиз с тегом `v<версия>` и приложить `dist/Vahta-Setup-<версия>.exe`:

   ```bash
   gh release create v0.6.0 dist/Vahta-Setup-0.6.0.exe --title "Вахта 0.6.0" --notes "…"
   ```

База игр для подсказок обновляется отдельно, без выпуска версии:
`tools/games.py` собирает `games.json.gz` и печатает, как выложить его
в пререлиз с тегом `games`.

## Планировщик

Фармить можно одну игру за раз, у кампаний свои окна и дедлайны — это
однопроцессорная задача с прерываниями. В учебном виде для неё оптимален EDF
(алгоритм Хорна): всегда работать над тем, у чего дедлайн ближе.

**Но у нас очередь строится не по дедлайну, а по запасу**, и разница
принципиальная. EDF оптимален, когда работать можно в любую минуту; эфирные
минуты приходят со своей скоростью, и «догнать потом» получается не всегда —
редкую кампанию физически нельзя отсмотреть быстрее, чем по игре идёт эфир.
Значит ей надо начинать раньше, даже если дедлайн у неё дальше. Запас
(`дедлайн − сейчас − остаток / доступность`) это знает, дедлайн — нет. Цель —
забрать все дропы, а не соблюсти порядок дедлайнов.

Поправка к учебной задаче: прогресс капает только когда живой стример
с дропсами в эфире, а по нишевой игре это шесть часов в сутки, а не двадцать
четыре. Отсюда две величины, и путать их нельзя:

- **просмотр занимает календарь один к одному** — смотреть можно только одно
  за раз, и здесь машина честно одна;
- **ожидание эфира календарь не занимает вовсе** — пока по игре никто
  не стримит, «Вахта» смотрит другую.

Поэтому задача **не владеет** отрезком календаря длиной `минуты / доступность`,
а набирает свои минуты со скоростью не быстрее доступности эфира, деля календарь
с остальными: сумма скоростей не больше единицы. Все кампании идут сразу
и вперемешку, свободное время остаётся в конце; редкая кампания тянется неделю,
но занимает в этой неделе свои восемь процентов, а не всю. Долю эфира берём
из `uptime_sample`; пока замеров меньше восьми, игра считается доступной всегда,
а оценка помечается как оптимистичная.

Прежняя модель резервировала календарь целиком, и на живых данных это выглядело
так: Overwatch с 600 минутами эфира при доступности 8% забирал пятеро суток
одним блоком, а League, Arena и Marvel Rivals вставали в очередь за ним. Служба
при этом вела себя правильно — нет канала, окно уходит следующей задаче, — так
что план врал не только на словах, но и относительно самой программы.

**Плану нужен исполнитель, который его слушает.** Обходчик держит игру ломтём
в `SLICE_MINUTES` минут и возвращает решение автопилоту, а тот заново идёт
по плану сверху вниз; сам план пересобирается не чаще `REPLAN_AFTER`, потому что
это обход каталога по сети. Никакой бухгалтерии долей в исполнителе нет и не
нужно: правило «смотрим того, кто выше в очереди и у кого сейчас есть канал»
даёт те же доли само. Без ломтя игра с живым каналом держала окно часами — тем
прочнее, чем популярнее, — и кампании, кончавшиеся в тот же день, сгорали.

Ещё одна вещь, которую легко понять неправильно: **прогресс внутри кампании
общий**. Дропы — это вехи на одном потоке просмотра (60, 120, 180 минут),
а не отдельные задачи. Работа кампании = самая дальняя веха минус отсмотренное,
а не сумма остатков.

Отсюда же следует, что **«не влезает» не значит «нечего фармить»**: нехватка
двадцати минут означает, что не возьмём последнюю веху, а ближние заберутся как
обычно. Поэтому план говорит «успеем 2 дропа из 3» и ничего не требует, а выбор
(«отказаться от такой-то кампании») предлагает только когда проверил пересчётом,
что от этого дропов станет больше. Отказ от кампании, у которой вехи ещё
достижимы, был бы строго хуже, чем не делать ничего.

И **ноль доступности при достаточной статистике — это приговор, а не скорость.**
Кампанию, которую фармить нельзя вовсе (например, она идёт только на своих
каналах, а те не в эфире), планировщик не берёт совсем, вместо того чтобы
обещать по проценту календаря в сутки. Она видна отдельной строкой с причиной
и вернётся в план сама, когда канал появится.

## Тесты

Сети не требуют. Каждый файл — отдельный скрипт:

```bash
for t in tests/test_*.py; do python "$t" || echo "FAIL $t"; done
```

В PowerShell:

```powershell
Get-ChildItem tests	est_*.py | ForEach-Object { python $_.FullName; if ($LASTEXITCODE) { "FAIL $_" } }
```

## База

`data/vahta.db`, SQLite. Копится сама во время `watch`:

| таблица | что лежит |
|---|---|
| `game`, `campaign`, `drop_item` | справочник — чтобы история жила, когда кампания уйдёт с Twitch |
| `claim` | что и когда забрано самой «Вахтой» |
| `reward` | своя копия инвентаря Twitch: все награды аккаунта, включая полученные до «Вахты» |
| `watch_session` | канал, кампания, засчитанные Twitch минуты |
| `watchlist` | игры, за которыми следим, в порядке приоритета |
| `uptime_sample` | был ли в этот момент эфир с дропсами по игре |

В `watch_session` идут именно те минуты, которые засчитал Twitch, а не время
работы программы — иначе часы врали бы при каждом падении стрима.
`uptime_sample` — сырьё для планировщика: он должен считать эфирное время,
а не календарное.

`reward` — копия, а не источник: у Twitch она берётся при каждом обходе, но
показывается своя, потому что без сети и с протухшим токеном Twitch не отдаёт
инвентарь вовсе. Отсюда же «что нового с прошлого раза»: столбец `seen`
снимается, когда человек открыл экран, а первое наполнение таблицы новостями
не считается — иначе первый запуск сообщил бы о каждой из 137 наград.
